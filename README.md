# Career Quest · NeonCode

Проект платформы развития сотрудников для трека Halyk Bank / HackAlem: рабочее frontend-демо и отдельная основа backend API.
Спокойный светлый интерфейс с зелёными акцентами, адаптированный для телефона и десктопа.

## Запуск

Требуется Node.js 20.9+ и npm. Из корня репозитория:

```sh
npm --prefix frontend ci && npm --prefix frontend run dev
```

Откройте http://localhost:3000. Для production: `npm --prefix frontend run build`, затем `npm --prefix frontend start`.

## Возможности

- Обзор сотрудника: карьерная цель, готовность и до трёх объяснимых рекомендаций.
- Траектория: выбор, изменение и снятие карьерной цели; требования целевой роли и уровня. Без выбранной цели — развитие на текущем уровне, в том числе для Lead.
- Каталог: поиск, фильтры, условия участия, запись на добровольные активности.
- Завершение активности в демо: пересчёт уровней с учётом gain / max_level.
- История: статусы и фильтрация, сохранение изменений в localStorage.
- HR: разрывы по навыкам, готовность к выбранным целям и отсутствие завершений за 90 дней. Без публичного рейтинга. Для HR и импорта выберите «Демо-роль → HR».
- Импорт JSON профилей и CSV истории, включая проверочные профили жюри. Файлы проверяются и применяются вместе; ошибка не меняет текущие данные. Совпадающие ID обновляются.

Дата демо — **2026-10-01**, согласно README датасета. Интерфейс и содержимое доступны на русском, английском и казахском. Имена людей, названия технологий и идентификаторы сохраняются без изменений.

## Языки / Languages / Тілдер

Кнопки **РУС / ENG / ҚАЗ** в верхней панели переключают язык без перезагрузки и сброса текущего экрана, профиля или прогресса. Предпочтение хранится отдельно в `career-quest-locale`. По умолчанию используется русский; некорректное сохранённое значение игнорируется. При недоступном localStorage переключение работает до закрытия страницы.

Use **РУС / ENG / ҚАЗ** in the header to switch between Russian, English and Kazakh. Your choice is remembered in this browser. All screens, activity descriptions, skills, roles, messages and dates are localized; switching languages preserves your current work.

Орыс, ағылшын және қазақ тілдерін ауыстыру үшін жоғарғы панельдегі **РУС / ENG / ҚАЗ** батырмаларын басыңыз. Таңдауыңыз осы браузерде сақталады. Барлық экрандар, іс-шара сипаттамалары, дағдылар, лауазымдар, хабарламалар және күндер аударылған. Тілді ауыстырғанда жұмысыңыз сақталады.

Переводы: `frontend/src/lib/locales/{ru,en,kk}.json`. Общие функции и контекст: `i18n.ts`, `locale-context.tsx`. Переводится только отображение: исходные значения ролей, грейдов, ID и формат импортируемого датасета неизменны. Поиск поддерживает локализованные и исходные названия. Для новых строк добавляйте ключи во все три словаря; динамические значения передавайте параметрами `{0}`, `{1}`. Тесты проверяют полноту словарей, параметры, языки всех экранов, мобильную вёрстку и сохранение состояния.

## Текущее состояние

Backend находится в `backend/app/`: FastAPI, SQLite и загрузчик датасета. Запуск и контракт описаны в [backend/README.md](backend/README.md). Фронтенд пока не вызывает этот API. Рекомендации, завершение, импорт и HR на сервере остаются заглушками; в интерфейсе эти сценарии работают локально.

Подробная проверка структуры, смысла и соответствия ТЗ: [docs/PROJECT_REVIEW.md](docs/PROJECT_REVIEW.md).

## Границы фронтенд-демо

Живой LLM пока не подключён. Подбор использует прозрачный многофакторный алгоритм, **не является AI-рекомендацией** и явно обозначен в интерфейсе. Учитываются целевая роль/грейд, критичность и прирост навыка, условия участия, история завершений/пропусков и длительность. Обязательные активности не рекомендуются. Исторические завершения после последней оценки применяются к профилю в хронологическом порядке.

Переключатель профиля и HR-экран предназначены для демонстрации на синтетических данных. На backend есть разграничение маршрутов по доверенным демонстрационным заголовкам, но нет проверяемой аутентификации; frontend-права с ним не связаны. Данные поставляются в клиентском bundle. Не использовать для реальных персональных данных без backend, контроля доступа и замены локального хранения.

Запись и завершение изменяют только локальное состояние браузера; интеграции с LMS, календарём и сервером отсутствуют. Выбранные профиль и цель сохраняются в браузере. При отсутствии даты оценки в профиле исторические завершения не прибавляются к текущим уровням; новые демо-завершения учитываются отдельно. Для сброса удалите ключ `career-quest-v1` из localStorage.

## Структура и интеграция

- `frontend/src/components/career-app.tsx` — оболочка приложения и навигация.
- `frontend/src/features/` — отдельные экраны сотрудника, каталога, истории, HR и импорта; контекст и управление демо-состоянием.
- `frontend/src/lib/domain.ts` — явные типы предметной области, независимые от JSON-примера.
- `frontend/src/lib/validation.ts`, `import-data.ts` — валидация и атомарный импорт.
- `frontend/src/lib/api/adapters.ts` — преобразование DTO текущего API в модели UI; реальные HTTP-вызовы пока не подключены.
- `frontend/src/lib/career.ts` — расчёты прогресса, предложений целей, рекомендаций и допустимости записи.
- `frontend/src/lib/dataset.json` — подготовленный синтетический датасет.
- `frontend/scripts/prepare-data.mjs` — воспроизводимая подготовка из `dataset/case_1/career_quest_dataset`.
- `frontend/tests/career.spec.ts` — расчёты и браузерные сценарии.

При подключении существующего backend замените начальную загрузку и localStorage на авторизованный API, перенесите HR-данные за серверный контроль доступа, а функции recommendations / enroll / complete — на вызовы сервисов. Сохраните формат объяснения: разрыв навыка, требование цели, ожидаемый прирост и факторы истории.

## Проверки

```sh
cd frontend
npm run lint
npm run build
npx playwright install chromium
npm test
```

`npm run data:prepare` обновляет клиентский датасет после изменения стартовых файлов. `npm run format` форматирует исходники.

## Git

Рабочая ветка фронтенда: `features/frontend`. Последовательность слияния после проверок: `features/frontend` → `dev` → `main`. Изменения фиксируются коммитами в рабочей ветке. Перед публикацией нужно синхронизировать удалённые ветки; force push не используется.
