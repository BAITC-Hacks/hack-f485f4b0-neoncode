# Проверка проекта — 23 сентября 2026

Состояние после объединения frontend и backend в `dev`.

**Вывод:** структура подходит для хакатонного MVP, фронтенд работает как самостоятельное демо. Приложение пока не реализует сквозной сценарий Career Quest из ТЗ: UI, серверное состояние и AI не связаны.

## Что проверено

- Сопоставление с ТЗ Career Quest и правилами стартового датасета.
- Структура Next.js, локализация, расчёты, импорт, восстановление состояния.
- FastAPI, конфигурация, схемы, маршруты, загрузчик, ограничения БД и тесты.
- Браузерные сценарии на русском, английском и казахском, мобильная ширина.
- Backend запущен через TestClient с настоящим стартовым датасетом в отдельной временной SQLite: `/api/employees` вернул 200 профилей. Рабочая БД не изменялась.

## Обновление после исправлений фронтенда

В `feature/frontend` закрыты самостоятельные фронтенд-замечания: добровольный выбор цели и корректный режим Lead, объяснение смены роли, разбиение экранов, вычисления HR только в HR-разделе, явные модели и адаптеры API, обработка nullable-полей, причины недоступности записи, атомарный импорт и сохранение выбранного профиля. Добавлены отдельные демонстрационные режимы сотрудника и HR; это не замена серверной авторизации. Исправлен учёт новых демо-завершений в день оценки.

В текущем фронтенде проходят **30 тестов**, lint и production build. Backend в этой итерации не менялся. Интеграция API, LLM и настоящая авторизация по-прежнему зависят от серверных возможностей и согласования контракта.

## Исходные замечания и текущий статус

### P0 — нет единого рабочего сценария

**Frontend не вызывает backend.** `career-app.tsx` читает клиентский JSON и localStorage. Изменения профилей и завершений не попадают в SQLite; серверные данные не появляются в UI. Проверочные профили жюри проходят только через локальный импорт браузера.

**Серверная бизнес-логика — заглушки.** В `backend/app/routers/employees.py` рекомендации возвращают пустые `recommendations/gaps` и `status=not_implemented`; завершение возвращает 501 без записи. В `routers/hr.py` импорт возвращает 501, HR — пустые метрики. Файлы `gaps.py` и `llm.py` содержат `NotImplementedError`. Это подтверждено запросами к приложению, а не только чтением кода.

**Нет AI-рекомендаций.** Клиентский многофакторный подбор — корректно обозначенный демо-алгоритм, но он не закрывает AI-ядро ТЗ. Нужны отбор допустимых кандидатов, LLM, проверка выбранных ID и аргументации, ограничение времени и работающий локальный fallback. Наличие `LLM_API_KEY` сейчас не включает LLM.

### P1 — интеграция и доступ

**Авторизация условная.** `get_identity()` доверяет заголовкам `X-Role` и `X-Employee-Id`; любой прямой клиент может заявить роль HR. Фронтенд отдаёт весь синтетический датасет и показывает HR любому посетителю. Для реального разграничения прав сервер должен получать личность из проверенной сессии/токена. CORS не является авторизацией.

**Разные источники данных.** Фронтенд использует 200 сотрудников / 40 событий / 60 навыков организаторов. Backend по умолчанию — 10 / 8 / 15 из `backend/data/synthetic`. Загрузчик поддерживает исходный датасет, но при смене `DATA_DIR` требуется отдельная БД: seeding добавляет отсутствующие ID, а не заменяет набор. При интеграции выбрать один источник и стратегию миграции.

**Контракт ещё не покрывает интерфейс.** Нет API каталога событий, справочника навыков, истории и записи в план. `HRSummaryResponse` содержит общие счётчики, но не срез дефицитов компетенций, требуемый ТЗ. Названия полей событий отличаются: API использует `audience/skills`, frontend — `target_roles/target_grades/develops_skills`. До подключения согласовать DTO и адаптер. Схемы и модели во время проверки не менялись.

**Запуск полного приложения одной командой отсутствует.** Есть отдельные команды frontend и backend; Docker Compose или общего dev-скрипта нет. Добавлять общий запуск имеет смысл вместе с реальным подключением UI к API, чтобы не выдавать два независимых демо за интеграцию.

### P2 — смысл и сопровождение

**Исправлено — цель без согласия сотрудника.** При `career_goal=null` теперь отображается развитие в текущей роли. Предложенный следующий уровень не становится целью до сохранения сотрудником. Lead может выбрать новое направление или остаться в своей роли; ложного следующего этапа Lead нет.

**Исправлено в UI — переход между ролями.** В данных 28 целей со сменой роли. UI отдельно показывает текущую и целевую роль, объясняет ограничения аудитории и предлагает обсудить переходную программу с HR при отсутствии подходящих шагов. Ограничения каталога сохранены; создание новых переходных программ относится к наполнению продукта.

**Исправлено — слишком крупный компонент.** Оболочка `career-app.tsx` сокращена примерно до 250 строк. Экраны вынесены в `features`, состояние — в отдельный hook/context, общие элементы — в `components/ui`, импорт и валидация — в `lib`. HR-аналитика вычисляется только в своём экране и мемоизирована; история индексируется по сотрудникам.

**Исправлено — типы зависят от JSON-примера.** Введены явные `Employee/Event/History/RoleProfile` и другие модели в `domain.ts`; адаптеры текущих DTO — в `lib/api/adapters.ts`. Пустые имя/отдел безопасно заменяются ID/ролью, отсутствие даты оценки явно обозначается и не приводит к повторному прибавлению исторического прогресса. Адаптеры не включают HTTP-интеграцию с заглушками.

**Лишний каркас backend.** Активное приложение — `backend/app`; `backend/career-quest-backend` содержит второй `pyproject.toml`, lockfile и приложение-заготовку. Backend README уже помечает его неиспользуемым. После подтверждения отсутствия зависимостей удалить или архивировать, чтобы команда не запускала неправильный сервер. В ходе проверки чужой каркас не удалён.

**Ограничения демонстрации.** Кнопка завершения сразу меняет статус, без подтверждения LMS; прогноз готовности не является решением о повышении. Жёсткая дата `2026-10-01` соответствует стартовому датасету и сейчас оправданна. В production время и подтверждение завершений должны определяться сервером.

## Исправлено в этой проверке

- CORS backend приведён к Next.js на `localhost:3000` и `127.0.0.1:3000`; неизвестные источники по-прежнему отклоняются.
- Проверяются реальные календарные даты и граница даты среза, непустые ID и объект навыков.
- История проверяет ссылки, уникальность ID, согласованность статуса и процента выполнения.
- Повторное завершение неповторяемого добровольного события отклоняется. Повторяемый клуб и обязательные ежегодные курсы из исходных данных сохраняют допустимые повторения.
- Повреждённая история из localStorage больше не применяется; восстановление профилей и истории атомарно, с возвратом к исходному датасету.
- CSV с повторяющимися заголовками или неправильным числом полей отклоняется.
- Будущие завершения не увеличивают текущие уровни навыков.
- Новые ошибки переведены на три языка; обновлён устаревший корневой README.

## Проверки и их пределы

- Frontend: lint, production build, **22 теста прошли**.
- Backend: **31 тест прошёл**, Ruff check и format check прошли.
- Исходные 200 профилей и 2 743 записи проходят усиленную frontend-валидацию.
- Backend с исходным датасетом возвращает 200 профилей; рекомендации и HR подтверждены как заглушки.
- Backend выдаёт предупреждение о будущем прекращении поддержки httpx в TestClient; это не падение тестов. Зависимости во время проверки не обновлялись.
- Не проверены живой LLM, сквозное API-взаимодействие, production-авторизация и целевые задержки AI: эти возможности ещё не реализованы. Зеленые тесты заглушек не подтверждают готовность к защите.

## Рекомендуемый порядок работы

1. Утвердить единый датасет и API для событий, истории, записи, рекомендаций, импорта и HR-дефицитов.
2. Реализовать серверный расчёт навыков, разрывов и идемпотентное завершение, затем атомарный импорт.
3. Добавить LLM поверх допустимых кандидатов с валидируемым объяснением и fallback.
4. Подключить UI, заменив localStorage и клиентский датасет серверным состоянием, сохранив отдельный явный демо-режим.
5. Ввести проверяемую авторизацию, разделить экраны по правам, добавить общий запуск.
6. Провести сквозной тест: импорт профиля жюри → рекомендация → завершение → пересчёт навыков → HR-срез; измерить задержки по ТЗ.
