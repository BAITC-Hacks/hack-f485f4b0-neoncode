# ÖSU frontend

Основной вход: React + Vite + TypeScript, React Router и TanStack Query.
Существующее автономное демо сохранено на `/demo`, включая русский, английский
и казахский интерфейс. API-экраны пока на русском языке.

```sh
npm ci
npm run dev
```

Откройте http://localhost:5173. Backend должен быть запущен отдельно на порту 8000.
Vite проксирует `/api` на `http://localhost:8000`. Изменения backend не требуются.

## API и маршруты

- `/me`: профиль выбранного сотрудника, серверные навыки, требования, рекомендации,
  завершение события и история.
- `/hr`: HR-сводка с диаграммой дефицитов и участием, без рейтингов.
- `/hr/employees`: список сотрудников, поиск по ID и фильтр по роли.
- `/hr/employees/:id`: профиль сотрудника для HR.
- `/hr/import`: JSON employees + history или файлы `employees_file` + `history_file`.
- `/demo`: прежнее автономное приложение, не связанное с серверной БД.

В шапке выберите HR, дождитесь списка сотрудников, выберите профиль и переключитесь
на «Сотрудник». Роль, выбранный ID и список известных ID сохраняются в
`career-quest-api-session-v1`. Запрос списка сотрудников выполняется только HR.
При смене идентичности кеш запросов очищается. Если localStorage недоступен,
приложение продолжает работать в текущей сессии с предупреждением.

`VITE_API_URL` задаёт **базовый URL с `/api`**, по умолчанию `/api`, например
`http://localhost:8000/api`. Пример находится в `.env.example`.
Переменная подставляется при запуске/сборке Vite; после изменения нужен перезапуск.
API-ключ LLM во frontend не передаётся. Production-образ содержит nginx с proxy
`/api` и SPA fallback на `index.html`. В другом окружении нужен эквивалентный
reverse proxy либо абсолютный `VITE_API_URL` и разрешённый CORS.
`vite preview` предназначен для локальной проверки сборки, не production-хостинга.

Все шесть операций проходят через `src/api/client.ts`, он один выставляет
`X-Role` и `X-Employee-Id`. Ошибки 401/403/422/500 показаны читаемо, для 422
сохраняется путь до поля. Рекомендации загружаются независимо от профиля;
таймаут клиента 15 секунд оставляет время на серверный LLM timeout и fallback.
Автоматические повторы отключены, чтобы не создавать лишние LLM-вызовы.

После успешного импорта или завершения запросы инвалидируются. Навыки не
пересчитываются на клиенте. `completion_id` хранится по паре сотрудник/событие,
включая повтор после сетевой ошибки и перезагрузки. UI отмечает одно завершение
для этой пары; новые повторные прохождения с другим ключом через UI не создаются.
Старый ответ идемпотентного повтора не подменяет актуальный профиль.

Типы генерируются из `../backend/docs/openapi.json`, вручную не редактируются:

```sh
npm run api:generate
npm run api:check
```

Генератор сохраняет необязательность полей с default (`--default-non-nullable false`).
Аудит существующих экранов и расхождений: [API_AUDIT.md](docs/API_AUDIT.md).

## Сценарии автономного демо (/demo)

- Роль «Сотрудник»: обзор, цель и траектория, каталог и история. «Демо-роль → HR» открывает аналитику и импорт; переключатель демонстрирует UX и не обеспечивает безопасность.
- Цель выбирается на экране траектории и сохраняется в браузере. Без цели прогресс относится к текущему уровню. Следующий уровень — предложение, Lead не получает ложное повышение до Lead.
- При смене роли показываются обе роли и условия доступности обучения. Каталог объясняет причину недоступной записи.
- Импорт применяется атомарно; повторный импорт во время обработки заблокирован. Обновлённый профиль задаёт новую базу оценки, и старые локальные отметки завершений больше не обходят её дату.
- Если дата оценки не задана, исторический прирост не применяется без подтверждённой базы. Новые завершения в демо учитываются, включая день последней оценки.
- Язык и выбранный профиль сохраняются. Если localStorage недоступен, приложение работает в текущей сессии и сообщает об ограничении сохранения.

## Структура

```text
src/
  app/                  страница, layout, стили, иконка
  components/           оболочка, общие UI-элементы
  features/
    career/             контекст и демо-состояние
    employee/           обзор, траектория, редактор цели
    catalog/            каталог, карточка и диалог активности
    history/            история сотрудника
    hr/                 HR-экран и чистая функция аналитики
    import/             экран загрузки файлов
  lib/
    domain.ts           явные типы предметной области
    data.ts             адаптер сгенерированного датасета
    career.ts           правила прогресса и доступности
    validation.ts       проверка профилей, истории и CSV
    import-data.ts      подготовка атомарного импорта
    api/adapters.ts     граница моделей UI и текущих DTO backend
    locales/            ru / en / kk
```

Живое приложение находится в `src/features/live/`, клиент и хуки в `src/api/`,
Vite-вход в `src/main.tsx`. Демонстрационный `use-career-state.ts` сохранён
отдельно: его локальные расчёты не используются на API-маршрутах. Исходный Next.js
вход и конфигурация сохранены; `dev:next`, `build:next`, `start:next` запускают
прежнее демо. Основной проверяемый сценарий запуска теперь Vite.

## Проверки

```sh
npm run lint
npm run typecheck
npm run api:check
npm run test:unit
npm run format:check
npm run build
npx playwright install --with-deps chromium
npm test
```

На Linux установка системных зависимостей Chromium может потребовать пароль
`sudo`; выполните её в обычном терминале. Ошибка запуска браузера
`libnspr4.so: cannot open shared object file` означает, что эти зависимости
ещё не установлены.

Playwright проверяет сохранённое демо и API-маршруты, включая роль, прямые ссылки,
ошибки импорта, обновление данных после завершения и мобильный viewport.
API в этих тестах подменён ответами по OpenAPI: реальные LLM-запросы не выполняются.
Vitest проверяет клиент, заголовки, пути, JSON/multipart, отмену и ошибки.
`npm run data:prepare` воспроизводит `dataset.json`; файл исключён из форматирования.

Текущее состояние всего проекта и серверные ограничения: [корневой README](../README.md), [отчёт проверки](../docs/PROJECT_REVIEW.md).
