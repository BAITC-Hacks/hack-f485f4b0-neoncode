# Аудит подключения API

Контракт: `backend/docs/openapi.json`. Проверка выполнена перед интеграцией.

| Область | Компоненты | Источник данных до интеграции |
| --- | --- | --- |
| Оболочка, роли, языки | `career-app`, `OpeningExperience`, `LocaleProvider` | React state, localStorage |
| Обзор сотрудника | `OverviewScreen` | Локальный датасет и расчёты |
| Траектория, цель | `TrajectoryScreen`, `GoalEditor` | Локальные требования, сохранение цели в браузере |
| Каталог | `CatalogScreen`, `EventCard`, `EventDialog` | Локальные события и запись в браузере |
| История | `HistoryScreen` | Локальная история и отметки завершения |
| HR | `HrScreen`, `teamAnalytics` | Локальные агрегаты и готовность к выбранной цели |
| Импорт | `ImportScreen`, `mergeImports`, validation | Разбор JSON/CSV и обновление браузерного состояния |

HTTP-запросов не было. `src/lib/api/adapters.ts` содержал только ручные DTO и
адаптацию. Проект запускался через Next.js, без Vite, React Router и TanStack Query.
Компоненты и бизнес-правила демо сохранены, доступны в `/demo`; прежние браузерные
тесты перенесены на этот адрес. Основные маршруты работают с API.

## Расхождения и решение

| Было | OpenAPI | Решение |
| --- | --- | --- |
| Ручные EmployeeDto/EventDto | Генерируемые схемы, nullable поля | `src/api/types.ts`; DTO старого адаптера ссылаются на генерацию |
| `target_roles`, `target_grades`, `develops_skills` | `audience.roles`, `audience.grades`, `skills` | API-экраны используют серверные поля без переименования; старый мост оставлен только для демо |
| Обязательные формат и длительность в демо | `format`, `duration_hours` могут отсутствовать или быть null | Живые рекомендации принимают такие события без ошибки; не придумывают расписание |
| Проверка API-профиля по встроенному каталогу навыков | Каталог сервера может отличаться | Убрана привязка `employeeFromApi` к synthetic-валидатору |
| История: строковый `completion_pct`, обязательный `record_id` | Число или null; `record_id` может отсутствовать | Живой экран отображает серверные значения напрямую |
| Локальные навыки после исторических завершений | `EmployeeProfile.skills`, `progress`, `history` | Нет повторного начисления на клиенте |
| Локальная карьерная цель управляет рекомендациями | Сервер рассчитывает следующий грейд текущей роли | Используются `progress`, `gaps`, `next_grade`, `remaining_points` |
| Завершение меняет локальную историю | POST с `event_id` и `completion_id`; ответ до/после | Mutation, стабильный ключ повтора, перечитывание актуального состояния |
| Локальные рекомендации | `status`, `source`, `score`, `factors`, `reasons`, `explanation` | Вывод серверных рекомендаций и явных пустых состояний |
| HR считает готовность сотрудников | Агрегаты дефицитов, группы без шага, участие | API-экран без ранжирования и сравнительных оценок людей |
| Импорт локальных файлов | JSON employees + history либо два multipart-файла | Передача на сервер, показ `loc/msg` при 422, обновление кеша |
| Все сотрудники доступны демо-роли employee | GET /employees только HR | Список загружается только HR; переключатель хранит лишь известные ID |

## Что намеренно не подключено

В OpenAPI отсутствуют каталог событий, каталог навыков, запись на событие,
редактирование карьерной цели и отдельный endpoint списка идентичностей.
Не добавлены вымышленные запросы. Эти возможности сохранены в автономном демо,
но не изображают серверные операции на живых маршрутах.

Роль в шапке является демонстрационным выбором, а не входом в систему. Backend
доверяет заголовкам. В режиме HR используется идентификатор `DEMO_HR`, который
не обязан существовать в таблице сотрудников. Список для выбора сначала нужно
загрузить в HR; при переключении в employee сохраняются только ID, не HR-профили.
Доступ к `/hr*` ограничен в интерфейсе; окончательное решение принимает backend.
